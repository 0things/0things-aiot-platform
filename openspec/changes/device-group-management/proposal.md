## Why

设备管理目前只有标签和设备列表，无法按业务组织设备，也没有对静态成员和动态筛选结果进行统一管理。现在引入分组，可以为设备运维、批量操作和后续权限控制提供稳定的资源边界；分组对外使用 UUID，避免暴露数据库自增主键。

## What Changes

- 新增设备分组资源，支持手动分组和动态分组两种类型。
- 分组采用扁平结构，不引入父子分组层级。
- 手动分组通过成员关系维护设备；动态分组通过受限规则实时计算设备成员。
- 新增动态规则校验和预览能力，禁止直接执行用户输入的 SQL。
- 分组及成员数据按组织隔离，设备可加入多个手动分组。
- 分组 API、设备列表分组筛选、设备详情分组展示和中英文界面。
- 分组 API 路径和返回值使用 `groupUuid`，不暴露内部 `id`。

## Capabilities

### New Capabilities

- `device-management/device-groups`: 管理扁平设备分组、成员和动态规则。

### Modified Capabilities

无。设备列表和设备详情入口作为本变更中分组能力的集成场景定义。

## Impact

- 后端新增分组模型、迁移、Repository、Service、Handler、Swagger 和测试。
- 后端设备查询需要支持按分组筛选，并复用设备标签、产品和状态条件。
- 前端新增分组管理页面、创建/编辑分组表单、动态规则预览和设备分组入口。
- 需要重新生成 GORM DAL、Swagger 和 Orval API 客户端。
- 不删除或改变现有设备标签 API；动态规则首期仅支持白名单字段和操作符。
